# Запуск эксперимента в Google Colab

Ноутбук `BTZSC_Colab.ipynb` клонирует код из `https://github.com/clinch0/ML2`
и запускает `experiment.py`. Встроенного архива и подключения Google Drive в нём нет.

## 1. Подготовка

1. Откройте <https://colab.research.google.com> и загрузите `BTZSC_Colab.ipynb`.
2. Выберите Runtime → Change runtime type → T4 GPU.
3. В ячейке 1 при необходимости измените `MODE`, `RUN_ID` и адрес `GIT_REPO_URL`.
4. Выполните ячейки сверху вниз. Ячейка 2 делает `git clone --depth 1` ветки `main`.

Репозиторий должен содержать `experiment.py` и `requirements-colab.txt`.
Все модели и датасеты публичные; для стандартного прогона токен не требуется.
Результаты сохраняются в `/content/runs` и доступны для скачивания в последней ячейке.
Скачайте архив до закрытия сессии Colab: локальное хранилище сессии временное.

## 2. Обновление ноутбука

После правки генератора выполните `python scripts/build_notebook.py`. Отдельный
`dist/colab_bundle.zip` собирается через `python scripts/package_for_colab.py`, но
ноутбук его не использует.

**Если GPU недоступен:** энкодеры считаются на CPU, а LLM получают
`SKIPPED_NO_GPU`. Дообучение на CPU может занять много времени.

**Частые ошибки:** если ячейка 2 не находит `experiment.py`, проверьте адрес
репозитория и ветку `GIT_BRANCH`. Пустой `colab_outputs_*.zip` означает, что
экспорт запущен до этапа оценки.

## 3. Порядок режимов и признаки успеха

**Обычный сценарий: ничего выбирать не нужно.** В ячейке 1 стоит `MODE = "all"` — жмите
Runtime → Run all, ячейка 8 прогонит всё по порядку и напечатает лог в реальном времени:

| Этап | Что делает | Признак успеха в логе |
|---|---|---|
| preflight | проверяет контракты датасетов, модели не грузит | `[preflight] OK за N с`, создан `preflight.json` |
| smoke | 20 примеров на датасет, все модели | `[smoke] OK`, в `results.csv` появились строки |
| evaluate | 300 примеров на датасет | `[evaluate] OK`; манифест пересоздаётся под 300 автоматически |
| finetune | дообучение rubert-tiny2 на `MonoHime` train ≤ 2000 | `[finetune] OK`, создан `ft_metrics.csv` |
| export | собирает `colab_outputs_<run_id>.zip` | `[export] OK`, в конце «итог: этапов OK 5/5» |

Итоговая строка `итог: этапов OK 5/5` и файл `run_all_report.json` — главный признак,
что прогон закончился целиком. Если какой-то этап упал, остальные всё равно выполняются,
а причина пишется в `errors.log` и в `run_all_report.json`.

Отдельные этапы (`MODE = "smoke"` и т. д.) остались для случаев, когда нужен только один шаг,
например перезапустить дообучение, не трогая оценку. Полезные флаги CLI:
`--with-smoke` (быстрая проверка на 20 примерах), `--no-finetune` и `--no-ru-extension` (выключают этапы, которые считаются по умолчанию).

**`preflight` не создаёт `results.csv` и `predictions.jsonl`** — он только проверяет контракты
датасетов. Экспорт сразу после него остановится с подсказкой, а не создаст пустой архив.

Между шагами полезно посмотреть ячейку 9 — она печатает `results.csv` и распределение статусов.

## 4. Продолжение после обрыва

Результаты лежат на локальном диске Colab. До завершения сессии скачайте архив
`colab_outputs_<run_id>.zip`. Если сессия уже закрылась, её локальные файлы
недоступны и прогон потребуется повторить. В пределах одной сессии повторный
запуск с тем же `RUN_ID` пропускает уже посчитанные пары и примеры.

## 5. Что скачать обратно

Файл **`colab_outputs_<run_id>.zip`** (шаг `export`). Состав:

| Файл | Содержимое |
|---|---|
| `results.csv` | строка на пару модель×датасет: метрики, ms/пример, время загрузки, VRAM, device/dtype/batch, status, reason |
| `summary.csv` | среднее macro-F1 и accuracy по модели (только строки `OK`) |
| `predictions.jsonl` | по одному предсказанию на пример: `run_key`, `sample_id`, `pred_index`, `gold_index` |
| `sample_manifest.csv` | выборка, на которой считались все модели (seed 42) |
| `manifest_info.json` | хэш манифеста и покрытие классов |
| `run_config.json` | режим, seed, N, список моделей и датасетов, `config_hash` |
| `environment.json` | python, torch, transformers, GPU |
| `errors.log` | все ошибки прогона с текстом исключения |
| `plots/*` | графики, если строились |
| `ft_metrics.csv`, `ft_config.json` | результаты и конфигурация дообучения (после `MODE=finetune`) |

## 6. Куда положить результат

Скачанный `colab_outputs_<run_id>.zip` положить в каталог **`incoming/`** репозитория
(именно с таким именем — скрипт извлекает `run_id` из имени файла), затем:

```bash
python scripts/import_colab_outputs.py incoming/colab_outputs_<run_id>.zip
```

Скрипт проверит структуру архива, пересчитает метрики из `predictions.jsonl`, запишет
`results/<run_id>/` и обновит раздел «Результаты» в `Эксперимент_BTZSC.md`.
Расхождения между `results.csv` из Colab и пересчётом выводятся явным списком.
